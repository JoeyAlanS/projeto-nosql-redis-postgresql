Roteiro: como demonstrar uma diferença e um erro
  1. Clique em Experimentar o CRUD e execute Criar em Ambos. O exemplo usa o ID 9000000010, fora da massa original.
  2. Execute Criar novamente: o console mostra HTTP 409, pois a leitura já existe.
  3. Escolha Redis, operação Atualizar, temperatura 33,50 °C e execute.
  4. Escolha Ambos e Consultar por ID, mantendo o ID do exemplo. O console destaca a diferença no campo temperature_centi.
  5. Escolha Excluir em Ambos para remover o exemplo. Consulte novamente: HTTP 404 significa que a leitura não existe.
As escritas alteram o banco selecionado. Em “Ambos”, PostgreSQL e Redis são executados em sequência, sem transação conjunta ou reversão automática. Os ensaios salvos de 1 e 5 milhões continuam na seção Testes de carga.

Histórico em um comando
Antes: índice de IDs → 200 hashes. Agora: o sorted set já contém as 200 leituras completas.
ZRANGE iot:opt:v1:sensor:501:full
-inf +inf BYSCORE LIMIT 0 200

      
Resumo atualizado nas escritas
Contagem, somas e alertas ficam agrupados por sensor e dia. O filtro combina os dias completos e consulta os registros das bordas parciais.
HGETALL iot:opt:v1:sensor:1:day:1793491200

    

    
Comparação justa por estratégia · medições reais
Mesmos registros, filtros, sete campos no resumo e ordem alternada. Q2 retorna as mesmas 200 leituras; Q3 usa pré-agregação nos dois bancos na comparação otimizada.
As variantes retornam os mesmos dados. A view PostgreSQL é atualizada antes do experimento; os resumos Redis acompanham o CRUD. O ensaio não contém escritas concorrentes: as duas estruturas estavam atualizadas. Estes tempos medem somente leitura com um cliente; não igualam custo de manutenção ou durabilidade. PostgreSQL pré-agregado venceu Q3 nestas medições.
